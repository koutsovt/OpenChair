## 1. `next.config.mjs`

Next.js 14 uses `.mjs` by default (Next.js 15+ supports `.ts`). For Next.js 14, use `.mjs` with JSDoc types.

```js
/** @type {import('next').NextConfig} */
const nextConfig = {
  // React strict mode is enabled by default since Next.js 13.4 for App Router
  // Explicitly set for clarity
  reactStrictMode: true,

  // Remove the X-Powered-By header for security
  poweredByHeader: false,

  // Image optimization: use remotePatterns (images.domains is deprecated in Next.js 14)
  images: {
    remotePatterns: [
      {
        protocol: 'https',
        hostname: '*.supabase.co',
        port: '',
        pathname: '/storage/v1/object/public/**',
      },
      {
        protocol: 'https',
        hostname: '*.supabase.in',
        port: '',
        pathname: '/storage/v1/object/public/**',
      },
    ],
  },

  // Turbopack config for dev (Next.js 14.x)
  // Use `next dev --turbo` flag; no config key needed in next.config.mjs
  // (Turbopack config via `experimental.turbo` was removed in later 14.x releases)

  // Opt into experimental features as needed
  experimental: {
    // Enable statically typed routes (optional, catches broken links at build time)
    // typedRoutes: true,

    // Server Actions are stable in Next.js 14
    serverActions: {
      bodySizeLimit: '2mb',
    },
  },
};

export default nextConfig;
```

**Key points:**

- `images.domains` is deprecated since Next.js 14. Use `images.remotePatterns` with protocol/hostname/pathname.
- For Supabase Storage, the hostname pattern is `*.supabase.co` and the path is `/storage/v1/object/public/**`.
- Turbopack is invoked via `next dev --turbo` CLI flag; no `next.config` key needed.
- `reactStrictMode: true` is the default for App Router since 13.4.

## 2. `tsconfig.json`

Generated by `create-next-app` and customized for `src/` directory with `@/` alias:

```json
{
  "compilerOptions": {
    "target": "ES2017",
    "lib": ["dom", "dom.iterable", "esnext"],
    "allowJs": true,
    "skipLibCheck": true,
    "strict": true,
    "noEmit": true,
    "esModuleInterop": true,
    "module": "esnext",
    "moduleResolution": "bundler",
    "resolveJsonModule": true,
    "isolatedModules": true,
    "jsx": "preserve",
    "incremental": true,
    "plugins": [
      {
        "name": "next"
      }
    ],
    "baseUrl": ".",
    "paths": {
      "@/*": ["./src/*"]
    }
  },
  "include": ["next-env.d.ts", "**/*.ts", "**/*.tsx", ".next/types/**/*.ts"],
  "exclude": ["node_modules"]
}
```

**Key points:**

- `"strict": true` enables all strict TypeScript checks.
- `"moduleResolution": "bundler"` is the Next.js 14 recommended setting (replaces `"node"`).
- `"baseUrl": "."` + `"paths": { "@/*": ["./src/*"] }` maps `@/` to the `src/` directory.
- `.next/types/**/*.ts` in `include` is required for Next.js App Router typed routes.
- Next.js automatically supports tsconfig `paths` — no webpack alias config needed.

## 4. `postcss.config.js`

Standard PostCSS config for Tailwind — this is minimal and rarely needs changes:

```js
/** @type {import('postcss-load-config').Config} */
const config = {
  plugins: {
    tailwindcss: {},
    autoprefixer: {},
  },
};

export default config;
```

Or the CJS version (used by `create-next-app`):

```js
module.exports = {
  plugins: {
    tailwindcss: {},
    autoprefixer: {},
  },
};
```

**Key points:**

- Only `tailwindcss` and `autoprefixer` are needed.
- No additional plugins required for Next.js.

## 5. ESLint Configuration

### For Next.js 14: Use `.eslintrc.json` (legacy format)

Next.js 14 ships with ESLint 8 and uses the legacy `.eslintrc.json` format by default. The flat config (`eslint.config.mjs`) is supported but requires manual migration with `@eslint/eslintrc` FlatCompat.

**Recommended: `.eslintrc.json` (legacy, stable for Next.js 14)**

```json
{
  "extends": ["next/core-web-vitals", "next/typescript", "prettier"],
  "rules": {
    "@typescript-eslint/no-unused-vars": [
      "warn",
      {
        "argsIgnorePattern": "^_",
        "varsIgnorePattern": "^_"
      }
    ],
    "@typescript-eslint/no-explicit-any": "warn",
    "prefer-const": "error",
    "no-console": [
      "warn",
      {
        "allow": ["warn", "error"]
      }
    ]
  }
}
```

**Required packages:**

```bash
npm install -D eslint eslint-config-next eslint-config-prettier
```

### Alternative: Flat config (`eslint.config.mjs`) for ESLint 9+

If you upgrade ESLint to v9 with Next.js 14, you need `@eslint/eslintrc` for backward compat:

```js
import { dirname } from 'path';
import { fileURLToPath } from 'url';
import { FlatCompat } from '@eslint/eslintrc';

const __filename = fileURLToPath(import.meta.url);
const __dirname = dirname(__filename);

const compat = new FlatCompat({
  baseDirectory: __dirname,
});

const eslintConfig = [
  ...compat.extends('next/core-web-vitals', 'next/typescript', 'prettier'),
  {
    rules: {
      '@typescript-eslint/no-unused-vars': [
        'warn',
        { argsIgnorePattern: '^_', varsIgnorePattern: '^_' },
      ],
      '@typescript-eslint/no-explicit-any': 'warn',
      'prefer-const': 'error',
      'no-console': ['warn', { allow: ['warn', 'error'] }],
    },
  },
  {
    ignores: ['node_modules/**', '.next/**', 'out/**', 'build/**', 'prisma/generated/**'],
  },
];

export default eslintConfig;
```

**Key points:**

- `next/core-web-vitals` is recommended — it upgrades Web Vitals rules from warnings to errors.
- `next/typescript` adds TypeScript-specific Next.js rules.
- `prettier` (from `eslint-config-prettier`) must come LAST — it disables ESLint rules that conflict with Prettier.
- Next.js 14 default is ESLint 8 + `.eslintrc.json`. Next.js 15+ defaults to ESLint 9 flat config.

```json
  "tailwindFunctions": ["cn", "cva", "clsx"]
}
```

**Required packages:**

```bash
npm install -D prettier prettier-plugin-tailwindcss eslint-config-prettier
```

**Key points:**

- `prettier-plugin-tailwindcss` MUST be the LAST plugin in the array. It auto-sorts Tailwind CSS classes.
- `tailwindFunctions: ["cn", "cva", "clsx"]` tells the plugin to also sort classes inside these function calls (commonly used with shadcn/ui's `cn()` utility).
- The plugin automatically finds `tailwind.config.ts` in the same directory.
- `eslint-config-prettier` disables conflicting ESLint formatting rules — ESLint checks logic, Prettier handles formatting.

## 7. `vitest.config.ts`

Official Next.js recommended configuration:

```ts
import { defineConfig } from 'vitest/config';
import react from '@vitejs/plugin-react';
import tsconfigPaths from 'vite-tsconfig-paths';

export default defineConfig({
  plugins: [tsconfigPaths(), react()],
  test: {
    environment: 'jsdom',
    globals: true,
    setupFiles: ['./src/test/setup.ts'],
    include: ['src/**/*.{test,spec}.{ts,tsx}'],
    exclude: ['node_modules', '.next', 'e2e'],
    css: false,
    coverage: {
      provider: 'v8',
      reporter: ['text', 'json', 'html'],
      include: ['src/**/*.{ts,tsx}'],
      exclude: ['src/**/*.d.ts', 'src/**/*.test.{ts,tsx}', 'src/**/*.spec.{ts,tsx}', 'src/test/**'],
    },
  },
});
```

**Setup file** (`src/test/setup.ts`):

```ts
import '@testing-library/jest-dom/vitest';
```

**Required packages:**

```bash
npm install -D vitest @vitejs/plugin-react jsdom @testing-library/react @testing-library/dom @testing-library/jest-dom vite-tsconfig-paths
```

**Add to `tsconfig.json` compilerOptions** (for global type support):

```json
"types": ["vitest/globals"]
```

**Key points:**

- `vite-tsconfig-paths` resolves `@/` aliases from tsconfig automatically — no manual alias config needed.
- `environment: "jsdom"` provides DOM APIs for React component testing.
- `globals: true` makes `describe`, `it`, `expect` available without imports.
- `css: false` skips CSS processing in tests (faster).
- Async Server Components are NOT supported by Vitest — use E2E tests (Playwright) for those.
- The official Next.js docs recommend `vitest.config.mts` but `.ts` works identically.

## 8. `prisma/schema.prisma`

```prisma
// Prisma schema for Supabase PostgreSQL

generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider  = "postgresql"
  url       = env("DATABASE_URL")
  directUrl = env("DIRECT_URL")
}

// ============================================
// Application Models
// ============================================

model Organization {
  id        String   @id @default(cuid())
  name      String
  slug      String   @unique
  createdAt DateTime @default(now()) @map("created_at")
  updatedAt DateTime @updatedAt @map("updated_at")

  members   Member[]
  events    Event[]

  @@map("organizations")
}

model Member {
  id             String   @id @default(cuid())
  userId         String   @map("user_id")
  organizationId String   @map("organization_id")
  role           Role     @default(MEMBER)
  phone          String?
  createdAt      DateTime @default(now()) @map("created_at")
  updatedAt      DateTime @updatedAt @map("updated_at")

  organization   Organization @relation(fields: [organizationId], references: [id], onDelete: Cascade)

  @@unique([userId, organizationId])
  @@map("members")
}

model Event {
  id             String   @id @default(cuid())
  title          String
  description    String?
  date           DateTime
  organizationId String   @map("organization_id")
  createdAt      DateTime @default(now()) @map("created_at")
  updatedAt      DateTime @updatedAt @map("updated_at")

  organization   Organization @relation(fields: [organizationId], references: [id], onDelete: Cascade)

  @@map("events")
}

enum Role {
  OWNER
  ADMIN
  MEMBER
}
```

**Key points:**

- `directUrl = env("DIRECT_URL")` is REQUIRED for Supabase. `DATABASE_URL` uses Supabase's PgBouncer connection pooler (port 6543); `DIRECT_URL` is the direct Postgres connection (port 5432) used for migrations.
- Use `@map("snake_case")` and `@@map("table_name")` to keep Postgres columns snake_case while using camelCase in TypeScript.
- Do NOT use `schemas = ["auth", "public"]` with `multiSchema` unless you specifically need to query Supabase Auth tables — it can corrupt Supabase Auth during migrations.
- For the Prisma singleton in Next.js, create `src/lib/prisma.ts`:

```ts
import { PrismaClient } from '@prisma/client';

const globalForPrisma = globalThis as unknown as {
  prisma: PrismaClient | undefined;
};

export const prisma = globalForPrisma.prisma ?? new PrismaClient();

if (process.env.NODE_ENV !== 'production') globalForPrisma.prisma = prisma;
```

```bash
# ============================================

NEXT_PUBLIC_APP_NAME="Your App Name"

# ============================================
# Auth (optional — if using NextAuth alongside Supabase)
# ============================================
# NEXTAUTH_URL=http://localhost:3000
# NEXTAUTH_SECRET=your-secret-here-generate-with-openssl-rand-base64-32

# ============================================
# Email (optional — Resend, SendGrid, etc.)
# ============================================
# RESEND_API_KEY=re_xxxxxxxxxxxxxxxxxxxxxxxxx

# ============================================

# ============================================
```

**Key points:**

- `NEXT_PUBLIC_` prefix exposes vars to the browser. NEVER prefix secrets with `NEXT_PUBLIC_`.
- Supabase connection strings come from Dashboard → Settings → Database → Connection string (or Connect → ORMs for Prisma-specific ones).
- `DATABASE_URL` MUST have `?pgbouncer=true` for the pooled connection.
- `DIRECT_URL` uses port `5432` (direct) vs `DATABASE_URL` port `6543` (pooled).
- Also create a `.env` file (committed, with empty placeholder values) and `.env.local` (gitignored, with real values).

## 11. `components.json`

shadcn/ui configuration file, generated by `npx shadcn@latest init`:

```json
{
  "$schema": "https://ui.shadcn.com/schema.json",
  "style": "new-york",
  "rsc": true,
  "tsx": true,
  "tailwind": {
    "config": "tailwind.config.ts",
    "css": "src/app/globals.css",
    "baseColor": "zinc",
    "cssVariables": true,
    "prefix": ""
  },
  "aliases": {
    "components": "@/components",
    "utils": "@/lib/utils",
    "ui": "@/components/ui",
    "lib": "@/lib",
    "hooks": "@/hooks"
  }
}
```

**Key points:**

- `"style": "new-york"` — the "default" style is deprecated. Use "new-york".
- `"rsc": true` — enables React Server Components support (for App Router).
- `"tsx": true` — generates TypeScript components.
- `"tailwind.config"` must point to your actual Tailwind config file path.
- `"tailwind.css"` must point to the CSS file that has `@tailwind base; @tailwind components; @tailwind utilities;`.
- `"tailwind.baseColor": "zinc"` — common choices: `zinc`, `slate`, `neutral`, `stone`.
- `"tailwind.cssVariables": true` — generates theme tokens as CSS variables (recommended).
- `"aliases"` must match your `tsconfig.json` paths. With `src/` directory, `@/` maps to `./src/*`.
- The CLI uses `aliases.ui` to know where to install UI components (e.g., `src/components/ui/button.tsx`).

## Package.json Scripts Reference

```json
{
  "scripts": {
    "dev": "next dev --turbo",
    "build": "prisma generate && next build",
    "start": "next start",
    "lint": "next lint",
    "lint:fix": "next lint --fix",
    "format": "prettier --write \"src/**/*.{ts,tsx,js,jsx,json,css,md}\"",
    "format:check": "prettier --check \"src/**/*.{ts,tsx,js,jsx,json,css,md}\"",
    "test": "vitest",
    "test:run": "vitest run",
    "test:coverage": "vitest run --coverage",
    "db:generate": "prisma generate",
    "db:push": "prisma db push",
    "db:migrate": "prisma migrate dev",
    "db:studio": "prisma studio",
    "db:seed": "prisma db seed",
    "postinstall": "prisma generate"
  }
}
```

**Key points:**

- `"build"` includes `prisma generate` before `next build` — required for Vercel deployments where cached `node_modules` may have stale Prisma Client.
- `"postinstall": "prisma generate"` ensures Prisma Client is regenerated after `npm install`.
- `"dev": "next dev --turbo"` enables Turbopack for fast dev server.
